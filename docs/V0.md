# QuantSift V0

## 产品目标

为个人投资者提供一个本地运行、结果可解释的日频量化研究台。系统从观察列表中筛出值得进一步研究的股票和基金，说明分数来自哪些指标，并显式展示数据日期与风险。

## 首版范围

- 市场：大陆 A 股、场内公募基金。
- 频率：日线收盘后刷新。
- 输出：观察列表排序、因子评分、推荐原因、风险提示。
- 信号：买入观察、继续观察、暂不交易。
- 执行：不连接券商，不自动下单。
- 数据：首个纵向切片使用录制样例；后续接入 AKShare provider 和 SQLite 缓存。

## 领域词汇

- `Instrument`：可被分析的股票或基金。
- `DailyBar`：标准化的单日 OHLCV 行情，包含来源、抓取时间和复权方式。
- `FactorScore`：某个公开因子的 0-100 分、权重和解释。
- `Recommendation`：针对一个标的、一个市场日期生成的研究结论。
- `buy_watch`：满足当前规则，进入人工买入研究清单，不等同于下单。
- `hold`：信号不足，继续观察。
- `avoid`：当前规则不支持发起新交易。

## 当前评分模型

综合分数由三个因子组成：

| 因子 | 权重 | 当前计算 |
|---|---:|---|
| 趋势 | 45% | MA5 相对 MA20 的位置 |
| 动量 | 35% | 20 个交易日价格变化 |
| 波动风险 | 20% | 日收益标准差年化后的反向评分 |

分数大于等于 70 为“买入观察”，45-69 为“继续观察”，低于 45 为“暂不交易”。阈值和权重将在引入回测后校准。

## 数据边界

UI 和策略只能依赖 `MarketDataProvider`，不得直接调用 AKShare、Tushare 或未来的付费数据接口。所有 provider 输出必须转换成标准 `Instrument` 和 `DailyBar`，以便缓存、回测和推荐引擎保持稳定。

## 数据源实现状态

- Python sidecar（`sidecar/quantsift_sidecar.py`）通过 stdio JSON-RPC 提供 `list_instruments` 与 `get_daily_bars`，底层调用 AKShare（A 股前复权日线、ETF 日 K、场外基金净值）。
- Tauri 侧 `src-tauri/src/sidecar/` 负责进程生命周期、重启与超时，并通过 `sidecar_list_instruments` / `sidecar_get_daily_bars` 命令暴露给前端。
- 前端 `src/data/provider-registry.ts` 默认优先 AKShare，失败时回退到离线样例，并在看板顶部显示数据源与回退提示。
- provider 契约测试使用录制 fixtures（`sidecar/fixtures/`），不依赖实时网络。
- 本地行情缓存层（`src/cache/`）：日线按标的与交易日写入本地存储，启动时先展示缓存结果再增量刷新；实时源不可用时缓存可离线兜底。存储接缝 `BarCacheStore` 预留 SQLite 适配器替换位。
